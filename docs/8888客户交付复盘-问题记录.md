# 8888 客户交付复盘 · 问题记录（原始素材）

> 记录时间：2026-07-06
> 场景：8888 元一对一代建，客户上门（在家交付）
> 交付内容：① 作业点评系统 ② 测评自动报告系统
> 耗时：昨晚 19:00 开始，至今日 14:00（约 19 小时）仍未完成

## 一、客户侧 / 基础环境问题

1. **部署额度中断**：用 Codex 部署，部署到一半额度耗尽，流程卡死
2. **网络不稳定**：机场质量差、流量不足，各环节反复失败
3. **账号体系混乱**：客户不理解每个账号各管什么用，分不清用途，操作过程中衍生出一堆新问题
4. **充值失败**：20 美元额度不够用，想升级 100 美元充不上（支付通道问题），又是一堆问题

## 二、自身 / 教学侧问题

5. **缺乏成型方法论**：目前靠与 AI 对话能把系统做出来，但没有一套稳定的、能立刻复制执行的交付 SOP——教学时给不出标准动作
6. **概念理解不足**：非专业出身，在 AI 辅助下能做出来，但部分技术概念理解不透，影响现场排错和讲解

## 三、过程中形成的产品洞察（顺手记下）

- 两套系统本质是**同一套固定工作流**：飞书表单填写 → 后台自动处理（AI）→ 飞书机器人推送报告。只是案例不同，能解决的问题非常多
- 正在研究的两个固定工作流提示词方向：(a) 测评系统 (b) 音频生成报告
- 已验证的结论：**这套东西两天现场教会客户自己搭，不可能**。必须走代建 / 交付路线

## 四、待办（整理飞书文档时展开）

- 每个问题对应一条预防动作 → 沉淀为「交付前检查清单」（账号清单 / 额度预检 / 网络备用方案 / 支付通道备份）
- 方法论问题 → 把固定工作流抽成标准模板 SOP（环境清单、账号清单、部署步骤、提示词槽位）
- 概念问题 → 把客户常问的概念整理成一页对客解释话术
